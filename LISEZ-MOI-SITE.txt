Mettre en ligne sur Hostinger
-----------------------------
Le site actuel est un Hostinger Website Builder. Il faut le remplacer par ces fichiers.

1. hPanel → Sites web → martinlisen.com → dans le menu du site, supprimer (ou
   « détacher ») le Website Builder du domaine. Hostinger propose alors de gérer
   le domaine avec un hébergement web classique.
2. hPanel → Hébergement → martinlisen.com → Gestionnaire de fichiers → public_html.
   Vider ce dossier (garder une copie si tu veux), puis déposer TOUT le contenu de
   Site_martinlisen/ (les fichiers .html, .htaccess, robots.txt, sitemap.xml et le
   dossier assets/). Le dossier Sources/ n'est pas nécessaire en ligne, mais ne gêne pas.
   Le dépôt se fait par glisser-déposer dans le Gestionnaire de fichiers, ou par FTP
   (identifiants dans hPanel → Fichiers → Comptes FTP).
3. Vérifier que l'index est bien index.html (hPanel → Avancé → Index du site, si proposé)
   et que le certificat SSL est actif (hPanel → Sécurité → SSL). Forcer le HTTPS.
4. Ouvrir https://martinlisen.com, https://martinlisen.com/labs.html et une URL
   inexistante (doit afficher la page 404 du site).

Variante recommandée : déploiement par Git (le site vit sur GitHub, Hostinger le clone)
1. Supprimer ou détacher le Website Builder, comme ci-dessus, pour que public_html soit vide.
2. hPanel → Sites web → martinlisen.com → Avancé → Git → dépôt
   https://github.com/nftmooods/Site-web, branche main, répertoire vide (= public_html) → Créer → Déployer.
3. Activer le déploiement automatique si proposé : chaque push sur main met le site à jour.

Variante : si tu préfères garder le Website Builder actif le temps de vérifier,
dépose le site dans un sous-domaine (ex. nouveau.martinlisen.com) puis bascule.

Modifier le site
----------------
Chaque page est un fichier .html complet : on peut corriger un texte directement dedans.

Pour éviter que l'en-tête et le pied de page divergent entre les pages, ils sont aussi
dans Sources/parts/ et le contenu de chaque page dans Sources/pages/. Après une
modification dans Sources/, regénérer les pages :

    python3 Sources/build-site.py

Règle : corriger à la source (Sources/), jamais seulement dans le fichier généré.
Si tu modifies un fichier .html à la racine sans passer par Sources/, la prochaine
regénération écrasera ta modification.

Les couleurs, typographies et rayons sont en tête de assets/css/site.css (:root).

Règles éditoriales tenues sur ce site
-------------------------------------
- Le texte est tourné vers le lecteur (tutoiement, « tu », sa situation, son problème),
  pas vers Martin. Accroches et pitchs parlent de ce que le lecteur vit et récupère ;
  le « je » reste réservé aux preuves vécues et à la bio (section « Qui est derrière »).
  Modèle d'accroche : un constat sur ce que tu fais, puis la contradiction en question
  (« Tu utilises l'IA pour gagner du temps. Alors pourquoi tu repars de zéro à chaque fois ? »).
- En façade : « Strates Digitales » + libellés plats (le média, le Lab, les ateliers,
  les formations, le podcast, l'accompagnement). Pas de Strate 0, de codes 0x01, de
  Stratagème ni de Stratège : c'est la taxonomie interne Notion.
- Un seul appel à l'action principal par page : « Réserver un échange » (Calendly).
  Le média et le Lab renvoient vers « Travailler avec moi ».
- Le Lab : un produit en vente porte son lien d'achat. Un produit en construction porte
  un « suis la suite ». Un produit abandonné renvoie vers « Travailler avec moi ».
- Aucun chiffre inventé. Le seul chiffre affiché est « 2 jours de gain » (Message de
  référence, preuve 1). Tout le reste est marqué [À FOURNIR].
- Question laissée ouverte (Plan de démarrage, 20/09) : sur une fiche produit en vente,
  ajouter ou non un second lien discret « besoin d'un outil sur mesure → Travailler avec
  moi ». Pour l'instant : non, un seul lien d'achat.
